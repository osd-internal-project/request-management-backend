# ระบบลงนามอิเล็กทรอนิกส์ (CD-14)

บริการกลางใน core-service (`services/core-service/src/esign/`) — Legal ใช้ส่งสัญญาลงนามก่อน, Delivery ใช้ต่อกับใบรับรองการตรวจรับภายหลัง.
ตัดสินใจกับผู้ใช้ 30 ก.ย. 2569: **ลงนามไฟล์ PDF ที่แนบ** (ไม่สร้าง PDF จากร่างเอง) · ช่องลงนามเป็น **ตำแหน่งสำเร็จรูป + หน้าลงนามท้าย** ·
OTP ส่งผ่าน **ช่องทางแบบเสียบได้ — mock ไปก่อน** (ยังไม่มี SMTP/SMS).

## ขั้นตอน

1. **แม่แบบช่องลงนาม (CD-165)** — `esign_layouts`: ต่อประเภทเอกสาร แต่ละช่องมีฐานะผู้ลงนาม, หน้า (`first`/`last`/เลขหน้า/`appendix` =
   หน้าลงนามที่ระบบแนบท้าย), ตำแหน่งสำเร็จรูป (`bottom-left` … `top-right`) และลำดับ · เอกสารที่สร้างแล้วคัดลอกช่องไว้ แก้แม่แบบไม่กระทบ
2. **สร้างเอกสารลงนาม** — Legal: `POST /contracts/:id/esign` จากไฟล์ PDF ในคลังสัญญา → `esign_envelopes` (ร่าง) เก็บต้นฉบับ + SHA-256
   (`originalHash`) · ทุกช่องต้องมีผู้ลงนาม: ภายใน (ผู้ใช้ในบริษัท) หรือภายนอก (ชื่อ + อีเมล/เบอร์)
3. **ส่งลงนาม (CD-166)** — `POST /esign/envelopes/:id/send`: ผู้ลงนามภายนอกได้ **ลิงก์ใช้ครั้งเดียว** (`/s/<token>` — เก็บเฉพาะ hash
   ของ token, ลิงก์แสดงในคำตอบครั้งเดียวให้ผู้ส่งคัดลอก จนกว่าจะมีอีเมล) · ผู้ลงนามภายในได้แจ้งเตือนในระบบเมื่อถึงลำดับ
4. **ยืนยันตัวตน (CD-167)** — ภายใน = ล็อกอิน (Keycloak) · ภายนอก = รหัส 6 หลักทางอีเมล/SMS (`EsignSender`, HMAC ด้วย
   `ESIGN_SECRET`, อายุ 10 นาที, ผิดได้ 5 ครั้ง, ขอใหม่ได้ทุก 1 นาที, ยืนยันแล้วเปิดลิงก์ได้ 30 นาที) · **mock เขียนรหัสลง log
   (ห้ามใน production)**
5. **รับลายมือชื่อ (CD-168)** — วาด / พิมพ์ / อัปโหลดภาพ (PNG/JPEG ≤ 500 KB) · ต้องเปิดอ่านเอกสารฉบับเต็มก่อน (บันทึก `viewed`)
   และติ๊กยินยอม · แบบเรียงลำดับต้องรอลำดับก่อนหน้าลงนามครบ
6. **ผนึก (CD-169) + ชุดหลักฐาน (CD-170)** — ลงนามครบ: `esign-seal.ts` (pdf-lib + ฟอนต์ Sarabun, OFL) วาดลายมือชื่อลงช่อง,
   เพิ่มหน้าลงนามท้าย (ถ้ามีช่อง `appendix`) และหน้าหลักฐาน (เวลา IP อุปกรณ์ วิธียืนยันตัวตน ประวัติการเปิดอ่าน ค่าตรวจสอบต้นฉบับ
   รหัสตรวจสอบ) → เก็บ `signedHash` · ประกาศ `esign.completed` → Legal เก็บฉบับลงนามในคลังสัญญาคู่ต้นฉบับ
7. **หน้าตรวจสอบเอกสาร (CD-173)** — `/v/<รหัส>`: แสดงผู้ลงนาม และให้เลือกไฟล์ — เบราว์เซอร์คำนวณ SHA-256 ส่งเฉพาะค่านั้นมาเทียบ

`esign_events` เป็นประวัติที่เขียนแล้วไม่แก้ (sent, notified, opened, otp_sent/verified/failed, viewed, signed, declined, sealed).

## เส้นทางสาธารณะ

`EsignPublicController` (`esign/public/*`, `esign/verify/*`) เป็น `@Public()` บน core-service — ดูเหตุผลใน AGENTS.md ·
เว็บเรียกผ่าน `/api/public/esign/*` ของ Next (allowlist path + rate limit ต่อ IP + ส่ง `x-forwarded-for` ต่อให้หลักฐาน).

## ค่าที่ต้องตั้ง

- `ESIGN_SECRET` (บังคับใน production) · `ESIGN_PUBLIC_URL` (URL ของเว็บ สำหรับลิงก์และหน้าตรวจสอบ) · `ESIGN_SENDER_MODE` (ตอนนี้ `mock`)
- สิทธิ์ `esign.manage` (seed ใส่ให้ role `legal`) — ส่งลงนาม/ตั้งแม่แบบ · การลงนามเองไม่ต้องมีสิทธิ์
- migration `20260930200000_esign` · packages `pdf-lib`, `@pdf-lib/fontkit`, `@fontsource/sarabun` (external ใน webpack — runner ต้องติดตั้ง
  production dependencies เหมือน pdf-parse)

## ยังไม่ทำ (กลุ่มที่สอง)

CD-171 เตือนซ้ำ/วันหมดอายุแบบแจ้งเตือน (การลงนามเรียงลำดับ/พร้อมกันทำแล้ว) · CD-172 ทะเบียนผู้มีอำนาจลงนาม · CD-174 ผู้ให้บริการใบรับรอง/ประทับเวลาภายนอก

## CD-172 ทะเบียนผู้มีอำนาจลงนาม (30 ก.ย. 2569)

- `esign_authorities` ต่อบริษัท: พนักงาน · ตำแหน่ง · วงเงิน (ว่าง = ไม่จำกัด) · ประเภทเอกสาร (ว่าง = ทุกประเภท) · ช่วงเวลา · ใช้งาน/ปิดใช้ ·
  หน้า **ทะเบียนผู้มีอำนาจลงนาม** (เมนูฝ่ายกฎหมาย, `esign.manage`) · API `GET/POST /esign/authorities`, `PATCH /esign/authorities/:id`
- ช่องในแม่แบบติ๊ก **ผู้มีอำนาจลงนามของบริษัท** (`authority`) → ต้องเป็นพนักงานที่มีรายการในทะเบียนครอบคลุมประเภทเอกสาร วันนี้ และ
  มูลค่า (`esign_envelopes.amount` — สัญญาใช้มูลค่าสัญญา) · ตรวจตอนสร้างเอกสาร **และตรวจซ้ำตอนเปิด/ลงนาม** (ปิดใช้หรือลดวงเงินระหว่างรอ
  = เปิดเอกสาร/ลงนามไม่ได้ 403) · กติกา `authorityFor` ใน `esign-rules.ts`
- ผู้ลงนามภายนอก (ฝั่งลูกค้า) ไม่ได้ตรวจกับทะเบียนนี้ — ทะเบียนเป็นของบริษัทเราเท่านั้น

## CD-160 ส่งสัญญาลงนาม

`POST /contracts/:id/esign` — สัญญาที่มาจากคำขอที่มีร่างในระบบ (CD-146) ต้องมีร่างที่ **อนุมัติแล้ว** (CD-159 — ซึ่งต้องผ่านความเสี่ยงและ
ขอบเขตงานมาก่อน) ไม่งั้น 409 · สัญญาที่บันทึกเองโดยไม่มีร่าง ส่งได้ตามปกติ
- migration `20260930220000_esign_authorities`

## CD-171 เตือนซ้ำและวันหมดอายุ (30 ก.ย. 2569)

- `EsignService.sweep` ทุกชั่วโมง (`ESIGN_SWEEP_INTERVAL_MS`, 0 = ปิด) ตามกติกาแจ้งเตือน **`esign.reminder`** (หน้าตั้งค่ากติกาแจ้งเตือน —
  ค่าตั้งต้น: เตือนทุก 2 วัน ไม่เกิน 3 ครั้ง, แจ้งผู้ส่ง 1 วันก่อนหมดอายุ):
  - ผู้ลงนามที่ **ถึงลำดับแล้ว** แต่ยังไม่ลงนาม: ภายใน = แจ้งเตือนในระบบ (`esign.reminder`) · ภายนอก = ส่งลิงก์เดิมอีกครั้งผ่าน `EsignSender`
    (ลิงก์เก็บแบบเข้ารหัส `tokenCipher` AES-GCM จาก `ESIGN_SECRET` คู่กับ hash — หา token ยังใช้ hash เท่านั้น)
  - ผู้ส่งลงนามได้แจ้ง `esign.expiring` ครั้งเดียวต่อกำหนด (ขยายเวลา = กำหนดใหม่ แจ้งใหม่ได้)
  - เลยกำหนด: สถานะ `expired` + แจ้งผู้ส่ง `esign.expired`
  - ทุกครั้งบันทึกเป็น event (`reminded`, `expiry_warned`, `expired`) — tick ซ้อนกันไม่ส่งซ้ำ
- `POST /esign/envelopes/:id/extend {days}` ขยายเวลา (เอกสารที่หมดอายุกลับมารอลงนาม) · `POST /esign/envelopes/:id/signers/:signerId/link`
  ออกลิงก์ใหม่ให้ผู้ลงนามภายนอก (ลิงก์เดิมใช้ไม่ได้ ต้องยืนยันรหัสใหม่) — แสดงครั้งเดียว
- migration `20260930240000_esign_reminders`
