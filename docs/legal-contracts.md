# CD-13 Legal — คลังสัญญา (CD-161)

ผู้ใช้ตัดสินใจ 29 ก.ย. 2569: คู่สัญญาเป็นลูกค้าในทะเบียน **หรือ** คู่สัญญาอื่น (ชื่อ+เลขภาษี) ·
สิทธิ์ใหม่กลุ่ม `legal.*` + สัญญาลับพิเศษรายฉบับ · ค้นข้อความในไฟล์ PDF ที่แนบ

## ข้อมูล

- ต่อยอดตาราง `customer_contracts` (CD-70) — `customerId` เป็น NULL ได้เมื่อมี `counterpartyName`
  (DB CHECK `customer_contracts_party_check`)
- `kind`: `standard` (ซื้อขาย/บริการ) · `nda` · `msa` · `other`
- `confidential` + `contract_access` (ผู้ที่เปิดได้เพิ่ม)
- `contract_documents`: ไฟล์ใน object storage (`contracts/<id>/<doc>/<name>`) + `textContent`
  ที่ดึงจาก PDF ตอนแนบ (`pdf-parse`; `textStatus` = extracted / empty (สแกน ไม่มี OCR) /
  failed / not_pdf)

## สิทธิ์

| สิทธิ์ | |
|---|---|
| `legal.contract.read` | ค้นดูคลังสัญญาทั้งบริษัท |
| `legal.contract.manage` | บันทึก/แก้ไข แนบ/ลบไฟล์ ตั้งลับพิเศษและรายชื่อผู้เข้าถึง — เห็นสัญญาลับทุกฉบับ |

สัญญาลับพิเศษ: เห็นได้เฉพาะ `legal.contract.manage` ผู้รับผิดชอบ ผู้บันทึก และรายชื่อใน `contract_access`
— ใช้กฎเดียวกันในแท็บสัญญาของหน้าลูกค้า (`contractVisibleWhere`) · คนอื่นเปิดด้วย id ได้ 404

seed เพิ่ม role **`legal` (ฝ่ายกฎหมาย)** · admin ได้ `legal.contract.read` อัตโนมัติ (สิทธิ์อ่าน) แต่ไม่ได้ manage

## API (core-service, หน้าจอเท่านั้น)

`GET /contracts?search=&text=&kind=&status=&ends_from=&ends_to=&min_value=&max_value=&confidential=` ·
`GET/PATCH /contracts/:id` · `POST /contracts` · `PUT /contracts/:id/access` ·
`POST /contracts/:id/documents` (multipart ≤ 25 MB: PDF/Word/JPEG/PNG) ·
`GET/DELETE /contracts/:id/documents/:documentId`

## ผลต่อของเดิม

- ต่ออายุสัญญา (CD-70) เปิดดีลต่ออายุเฉพาะสัญญาที่มีลูกค้าและชนิด standard/msa (NDA/สัญญาผู้ขายไม่เปิดดีล)
- webpack ปล่อย `pdf-parse` ไว้นอก bundle (โหลดจาก node_modules ตอนรัน เหมือน Prisma)

## ก่อนใช้งาน

รัน migration `20260929420000_contract_repository` + `prisma:seed` (สิทธิ์ `legal.*` และ role `legal`)
แล้วมอบ role ฝ่ายกฎหมายให้ผู้ใช้

# CD-148 NDA · CD-149 MSA

- **NDA** (สัญญาชนิด `nda`): คู่สัญญา วันมีผล/หมดอายุ (เดิม) + **ข้อมูลที่คุ้มครอง** (`ndaScope`) และ
  **ทิศทาง** (`ndaDirection` = mutual · disclosing เราเปิดเผย · receiving เรารับข้อมูล) — ชนิดอื่นล้างสองช่องนี้
- **MSA**: สัญญาใดก็อ้างอิงข้อตกลงหลักได้ (`masterContractId`) — ต้องเป็นชนิด `msa` ไม่ถูกยกเลิก
  **คู่สัญญาเดียวกัน** (ลูกค้าเดียวกัน หรือชื่อคู่สัญญาเดียวกันไม่สนช่องว่าง/ตัวพิมพ์) · MSA อ้าง MSA ไม่ได้ ·
  MSA ที่มีสัญญาย่อยเปลี่ยนชนิดไม่ได้ (`contract-links.ts`)
- **แก้ MSA → แจ้งทุกสัญญาย่อยที่ยังมีผล** (`ContractMasterNotifier`): แก้รายละเอียด / ข้อกำหนด / แนบ-ลบไฟล์
  → ผู้รับผิดชอบสัญญาย่อยแต่ละฉบับได้รับแจ้ง (`legal.msa.changed`, แก้ข้อความได้ที่หน้าข้อความแจ้งเตือน)
  ยกเว้นคนที่แก้เอง · การแจ้งล้มเหลวไม่ทำให้การแก้ล้ม
- หน้า MSA แสดง "สัญญาย่อยภายใต้ข้อตกลงนี้" · หน้าสัญญาย่อยลิงก์ไปข้อตกลงหลัก · migration `20260929460000_contract_nda_msa`

# CD-162 แจ้งเตือนหมดอายุ · CD-163 ติดตามข้อผูกพัน

- **CD-162** (`ContractExpiryService`, ทุกชั่วโมง): สัญญาที่ไม่ต่ออายุผ่านฝ่ายขาย — NDA, ชนิด "อื่น ๆ",
  และสัญญากับคู่สัญญาที่ไม่ใช่ลูกค้า — เตือนผู้รับผิดชอบตามกติกา `contract.expiry` (ค่าตั้งต้น 60/30/7 วัน)
  และแจ้งในวันที่หมด · สัญญาลูกค้าชนิดซื้อขาย/บริการ/MSA ยังใช้ CD-70 (เปิดดีลต่ออายุ + เตือน) เหมือนเดิม ·
  ขั้นที่เตือนแล้วเก็บใน `remindedDays` (เลื่อนวันสิ้นสุด = เตือนใหม่)
- **CD-163** (`contract_obligations`): ฝ่ายกฎหมายแตกข้อผูกพันจากสัญญา — สิ่งที่ต้องทำ ข้ออ้างอิง ผู้รับผิดชอบ กำหนด
  - ผู้รับผิดชอบได้รับแจ้งเมื่อได้รับมอบ เตือนก่อนกำหนดตามกติกา `contract.obligation` (ค่าตั้งต้น 3 วัน) และแจ้งครั้งเดียวเมื่อเลยกำหนด
  - หน้า **ข้อผูกพันของฉัน** (`/pages/obligations`, ทุกคนที่ล็อกอิน) — กด "ทำแล้ว" พร้อมบันทึก; ลิงก์ไปสัญญาเฉพาะคนที่เปิดสัญญาได้
  - ฝ่ายกฎหมายแก้/เปลี่ยนผู้รับผิดชอบ (แจ้งคนใหม่)/ยกเว้น/เปิดใหม่ได้ · ทุกการเปลี่ยนลง audit
  - API: `GET/POST /contracts/:id/obligations` · `PATCH /contracts/:id/obligations/:oid` · `GET /contract-obligations/mine` · `POST /contract-obligations/:id/done`
- migration `20260929480000_contract_obligations`

# CD-151 ระดับบริการ

การ์ดข้อกำหนดของสัญญามีส่วน **ระดับบริการ** (`contract_terms.serviceLevels` ฯลฯ) — ค่าที่วัดได้:
ชั่วโมงตอบกลับ/แก้ไขต่อระดับความรุนแรง (รูปแบบและกฎตรวจเดียวกับเป้าของประเภทเคส CD-67), การนับเวลา

# CD-164 แผนการวางบิลตามงวด

การ์ด **แผนการวางบิลตามงวด** บนหน้าสัญญา (`contract_installments`) — ทุกงวดตามลำดับ: ประเภท
(เงินมัดจำ / งวดตามความคืบหน้า / งวดสุดท้าย / เงินประกันผลงาน), จำนวนเงิน (กรอกเป็นเงินหรือ % ของมูลค่า),
กำหนดชำระ (วันที่ และ/หรือ เงื่อนไข เช่น "30 วันหลังตรวจรับ") และหมุดหมายที่ปลดล็อก

- **บันทึกทั้งชุด** (`PUT /contracts/:id/installments`, ลบ-สร้างใหม่ในทรานแซกชันเดียว) และบันทึกได้เมื่อ
  **ผลรวมเท่ามูลค่าสัญญาพอดี** — เทียบเป็นสตางค์ (`contract-installments.ts`) · ไม่พอดีตอบ 400 พร้อมบอกว่าขาด/เกินเท่าไร
- **เงินมัดจำ** ต้องบันทึกหลักประกันที่ออกคู่กัน (หนังสือค้ำประกันธนาคาร / เช็ค / เงินสด) วงเงินไม่น้อยกว่ายอดมัดจำ
  พร้อมเลขที่และวันหมดอายุ · งวดอื่นแนบหลักประกันได้ (เช่น ค้ำประกันแทนเงินประกันผลงาน)
- ทุกงวดต้องมีวันที่ เงื่อนไข หรือหมุดหมายอย่างน้อยหนึ่งอย่าง · งวดสุดท้ายมีได้งวดเดียว · สัญญาที่ไม่มีมูลค่าวางงวดไม่ได้
- หมุดหมายเป็นข้อความจนกว่า PM (CD-152) จะมี Milestone ให้ผูก · การออกใบแจ้งหนี้เข้า SAP เป็นงานถัดไป
- สิทธิ์: อ่าน `legal.contract.read` (ตามการมองเห็นของสัญญา) · บันทึก `legal.contract.manage` · ลง audit `legal.installments.saved`
- migration `20260929520000_contract_installments`

# CD-158 ประเมินความเสี่ยงกฎหมาย

การ์ด **ประเมินความเสี่ยงกฎหมาย** บนหน้าสัญญา (`contract_risk_assessments`, ฉบับปัจจุบันหนึ่งแถวต่อสัญญา
ฉบับก่อนหน้าอยู่ใน audit `legal.contract.risk_assessed`): ระดับ ต่ำ/ปานกลาง/สูง/วิกฤต, สรุปความเห็น, และประเด็น
(ข้อในสัญญา ระดับ รายละเอียด/ข้อเสนอ) ติ๊ก **เสนอผู้บริหาร** รายประเด็นได้

- **ต้องมีความเห็นผู้บริหาร** เมื่อระดับสูง/วิกฤต หรือมีประเด็นที่ติ๊กเสนอผู้บริหาร — ระบบสร้าง+ยื่นคำขอประเภทที่ตั้งใน
  หน้าตั้งค่า CRM ("ประเภทคำขอความเห็นความเสี่ยงทางกฎหมาย", `legalRiskOpinionTypeCode`) แบบเดียวกับ CD-153
  (`form_data`: subject, contract_no, counterparty, contract_value, risk_level, detail = ประเด็นที่เสนอ)
- ยังไม่ตั้งประเภท / สร้างไม่ได้ / ยื่นไม่ผ่าน → เก็บเหตุผลไว้บนการ์ด การประเมินยังบันทึกอยู่ · กด "ขอความเห็น" ส่งใหม่ได้
- ประเมินซ้ำด้วยระดับเดิมและประเด็นที่เสนอชุดเดิม = ใช้คำขอเดิม · เปลี่ยนระดับหรือประเด็นที่เสนอ = ขอใหม่ (`opinionKey`)
- ระดับสูง/วิกฤตต้องระบุประเด็นอย่างน้อยหนึ่งข้อ
- **`signing`** — ลงนามได้หรือยังในแง่ความเสี่ยง: ไม่ต้องเสนอ หรือผู้บริหารเห็นชอบ (คำขอ approved) = ได้ ·
  ยังไม่ได้ประเมิน = ไม่ระบุ · ระบบยังไม่มีขั้นลงนาม (CD-160) — CD-159/160 อ่านค่านี้
- API: `GET/PUT /contracts/:id/risk` · `POST /contracts/:id/risk/opinion`
- migration `20260929540000_contract_risk_assessment`

# CD-146 แม่แบบและร่างสัญญา

**แม่แบบ** (`contract_templates`, เมนู ฝ่ายกฎหมาย → แม่แบบสัญญา): ข้อสัญญาเรียงลำดับ (หัวข้อ + เนื้อความ)
ใส่ตัวแปร `{{ชื่อ}}` ได้ — รายการตัวแปรอยู่ที่ `DRAFT_VARIABLES` (`contract-drafts.ts`, `GET /contract-templates/variables`)
บวก `{{term_<รหัส>}}` ของเงื่อนไขการค้าที่ต่อรอง (CD-79) · ตัวแปรที่ไม่รู้จักบันทึกไม่ได้ · ข้อได้รหัส `c1..cN` ตามลำดับ

**ร่าง** (`contract_drafts` + `contract_draft_versions`) ผูกกับ **คำขอจัดทำสัญญา** (ประเภทที่ตั้งใน CRM, CD-81) หนึ่งร่างต่อคำขอ:
- หน้าคำขอมีการ์ด "ร่างสัญญา" (สิทธิ์ `legal.contract.read`) — ฝ่ายกฎหมายเลือกแม่แบบแล้วเริ่มร่าง = ฉบับที่ 1
- ค่าตัวแปรมาจาก form ของคำขอ (มูลค่า วันเริ่ม/สิ้นสุด คู่สัญญา) → ดีล (`ref_type=opportunity`) → ลูกค้าและที่อยู่
  (ที่อยู่ออกบิลก่อน) → รอบต่อรองล่าสุด → หัวกระดาษบริษัท · หาไม่เจอ = คง `{{ชื่อ}}` ไว้และแสดงว่า "ยังไม่มีค่า"
- บันทึกแต่ละครั้ง = ฉบับใหม่ (ฉบับเก่าไม่ถูกแก้ — CD-147 เทียบ, CD-159 อนุมัติ) · ส่ง `base_version`
  ถ้ามีคนบันทึกฉบับใหม่กว่าแล้วตอบ 409 · ข้อความไม่เปลี่ยนตอบ 409
- ทุกข้อทำเครื่องหมายเทียบแม่แบบที่เติมค่าแล้วตอนเริ่มร่าง: ตามแม่แบบ / **แก้จากแม่แบบ** (ดูข้อความเดิมได้) / **เพิ่มใหม่**
  และรายการข้อที่ตัดออก · แก้แม่แบบภายหลังไม่กระทบร่างที่เริ่มแล้ว
- คำขอปิดแล้ว (completed/closed/rejected/cancelled หรือยังเป็น draft) = ดูได้อย่างเดียว
- สัญญาในคลังที่มาจากคำขอ (`requestId`) มีลิงก์ไปร่างที่ใช้ทำ
- API: `GET/POST /contract-templates`, `PATCH /contract-templates/:id`, `GET /contract-drafts/by-request/:requestId`,
  `POST /contract-drafts`, `GET /contract-drafts/:id?version=`, `POST /contract-drafts/:id/versions`
- migration `20260929560000_contract_drafts`
